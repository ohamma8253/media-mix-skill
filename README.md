# media-mix — 매체 사이 운영 계획안 스킬

대행사 마케터와 묻고 답하며 광고주의 **다음 기간 운영 계획안**을 짜 주는 스킬이다. 운영 계획안은 네이버 · 카카오 · 메타 · 구글 네 매체 사이에 돈을 어떻게 나눌지와, 매체 안에서 어떤 광고 상품(예: 메타 판매 캠페인, 네이버 쇼핑검색)에 얼마를 둘지를 담은 안이다. 지금 판은 **v2.0(터미널판)**이다.

- **입구 둘**: 상시(거래 중인 광고주의 다음 달 계획) · 새 광고주(처음 내는 제안).
- **기간 모양 셋**: 평시 · 행사 · 장기(2개월 이상). 입구와 기간 모양은 겹쳐 쓴다(예: 새 광고주 · 행사).
- **결과**: 어떤 경우든 같은 묶음이 나온다 — 광고주에게 보여 줄 **계획안 표**(매체 · 상품별 금액 · 기간 · 예상 수치, 장기면 월별 방향표가 앞에 붙음), 계산과 규칙을 다시 본 **점검표**, **광고주에게 보낼 확인 메시지**, 들은 값과 가정을 모은 입력 정리, 다음 달에 이어 쓸 광고주 기록. 경우가 바꾸는 것은 그 안의 줄과 '해당 없음'뿐이다. 실제 모양은 [예시 결과물](docs/예시_결과물/00_목차.md)에서 본다.
- 계산은 식을 보이고, 들은 것만 쓴다. 모르는 값은 '확인 못 함'으로 두고 광고주에게 받을 것으로 넘긴다. 통계로 매체 기여를 재는 모형이 아니고, 캠페인 형식 · 세팅은 다루지 않는다.

**시험 · 예시에 나오는 광고주 이름과 숫자는 모두 지어낸 것**이다. 실제 계정의 데이터는 들어 있지 않다.

바뀐 것은 [`CHANGELOG.md`](CHANGELOG.md)에 있다.

## 설치
### 1. 받기
- [**media-mix.zip 바로 받기**](https://github.com/ohamma8253/media-mix-skill/raw/main/skill/media-mix.zip) — 저장소 파일 [`skill/media-mix.zip`](skill/media-mix.zip)과 같다. 풀면 `media-mix/` 폴더 하나가 나온다(`SKILL.md`와 `references/`).

### 2. 터미널 에이전트에 두기
폴더 이름은 `media-mix` 그대로 두고, 안에 `SKILL.md`와 `references/`가 있어야 한다.

| 어디서 | 둘 곳 |
|---|---|
| Claude Code | 모든 작업에서: `~/.claude/skills/media-mix/` · 한 작업 폴더에서만: `<작업 폴더>/.claude/skills/media-mix/` |
| Codex | `<작업 폴더>/.agents/skills/media-mix/` |
| 제미나이 CLI | `<작업 폴더>/.gemini/skills/media-mix/` |

받은 zip이 `~/Downloads/media-mix.zip`에 있다면:
```sh
# Claude Code (모든 작업에서)
mkdir -p ~/.claude/skills && unzip ~/Downloads/media-mix.zip -d ~/.claude/skills/   # → ~/.claude/skills/media-mix/SKILL.md

# Codex · 제미나이 CLI (작업 폴더 안에서 실행)
mkdir -p .agents/skills && unzip ~/Downloads/media-mix.zip -d .agents/skills/       # → .agents/skills/media-mix/SKILL.md
mkdir -p .gemini/skills && unzip ~/Downloads/media-mix.zip -d .gemini/skills/       # → .gemini/skills/media-mix/SKILL.md
```
- 여러 곳에 두었다면 새 판으로 바꿀 때 모두 같이 바꾼다(한 곳만 바꾸면 에이전트마다 판이 갈린다).
- 웹 대화(Claude 웹 · ChatGPT)에 올리는 판은 v1.3에서 멈췄고 이 저장소에는 없다.

### 3. 첫 말
- "새 광고주 제안용 미디어믹스 짜자" → 처음부터(입구 · 브랜드 · 쓸 수 있는 것 확인)
- "A사 다음 달 미디어믹스" + 지난달 광고주 프로필(또는 그 파일 경로) → 프로필 확인 + "지난달과 바뀐 것" 한 질문으로 시작
- "블랙프라이데이 행사 예산 1,000만 원 나눠 줘" → 행사 자료(대상 제품 · 기간 · 할인율 · 콘텐츠 올리는 날)를 받아 구간별로
- "12월~2월 신제품 출시 미디어믹스 짜 줘" → 장기: 월별 방향표 + 첫 달 계획안
- 계획안을 붙이고 "미디어믹스 점검만" → 점검만
- Claude Code는 `/media-mix`로 바로 부를 수도 있다. Codex · 제미나이 CLI에서 이름으로 부르는 법은 아직 써 보지 않았다. 말로 부르는 것이 기본이다.

### 4. 새 판으로 바꾸기
두었던 `media-mix/` 폴더를 지우고 새 zip을 같은 자리에 푼 뒤 새 세션으로 시작한다. 스킬 파일 머리의 '(v2.0 터미널판)'과 [`CHANGELOG.md`](CHANGELOG.md) 맨 위로 판을 본다.

## 쓰면서 알아 둘 것
- 한 번에 질문은 3개까지다. 새 광고주 · 평시라면 스킬이 대략 열 차례 답하면 산출물 한 벌이 다 나온다. 상시 광고주이고 프로필이 있으면 더 짧다.
- 계획안은 기본으로 작업 폴더에 파일로 쓴다 — 광고주용 본 · 내부본 · 근거 숫자(CSV), 마지막에 광고주 프로필. 광고주에게는 **광고주용 본만** 보낸다. 점검 결과 · 결과 박스는 내부본에 있다.
- 스킬은 광고 설정을 바꾸지 않고 메시지를 보내지 않는다.
- '(가안)'이 붙은 규칙은 아직 확정 전이다. 목록은 [`skill/media-mix/references/provisional.md`](skill/media-mix/references/provisional.md).

### 브라우저 — 사용자 설정 우선 · 읽기만 · 로그인은 사람
- 광고 관리자 · 자사몰 관리자 · 키워드 도구는 **마케터가 브라우저에서 직접 로그인해 둔다.** 스킬은 비밀번호 · 인증 코드를 받지 않는다.
- 브라우저는 이 순서로 고른다: ① 사용자가 정해 둔 브라우저 설정(쓰는 환경의 지침 · 기본 브라우저 도구)이 있으면 그대로 ② 없으면 쓸 수 있는 브라우저 도구로 ③ 못 읽으면 값 · 캡처 · 내보내기 파일로 받는다. 특정 브라우저 도구를 정해 두지 않는다.
- 화면은 "로그인해 둔 ○○ 화면을 읽어도 될까요?"라고 물은 뒤 **읽기만** 한다(설정 · 예산은 건드리지 않음). 내보내기 파일(CSV · XLSX)은 경로를 주면 직접 읽는다.

### 권장 모델
- 기본은 **소넷**.
- 행사를 다시 짜는 판 · 장기처럼 구간이 많은 판은 마지막 확인을 **오푸스**로 한다.
- **루나(gpt-6-luna)는 권하지 않는다**(두 번의 시험 모두 계획안 숫자가 무너졌다).
- 솔(gpt-6.1-sol) · 아스트라(gpt-6-astra)는 재시험 세 회차에서 오푸스 · 소넷과 비슷했지만, 표본이 작고 사용 한도에 쉽게 걸려 나머지 회차를 돌리지 못했다.
- 제미나이(agy로 돌린 gemini-3.8-flash)는 재시험에서 할당량에 걸려 재지 못했다.

## 어떻게 시험했나
에이전트가 마케터 역을 맡은 대화로, 다섯 상황(상시 · 행사로 다시 짜기, 새 광고주 · 예산 없음, 새 광고주 · 행사, 새 광고주 · 장기 출시, 자료가 엉성한 경우)을 여러 모델로 돌렸다. 시나리오의 광고주와 숫자는 지어냈다.
- **1차(10/30, v1 직전 판)**: 23회차를 돌렸다(그 밖에 1회차는 모델 용량 부족으로 멈춤). 오푸스 · 소넷은 다섯 상황에서 놓친 오류가 없었다. 제미나이는 한도 식을 돌리지 않고 '통과'로 적거나 들은 것 밖을 단정한 일이 많았고, 루나는 계획안 금액을 비우거나 진행을 줄였다. 고칠 곳 40건을 v1에 반영했다. 보고: [`docs/시험/스킬시험_v1.md`](docs/시험/스킬시험_v1.md)
- **재시험(11/3, v1)**: 30회차 가운데 15회차를 끝까지 돌렸다(Codex 사용 한도로 10회차, 제미나이 할당량으로 5회차를 못 돌림). 오푸스 · 소넷은 각 5회차 모두 끝까지 갔고 들은 것 밖 단정이 0이었다. 1차와 견줄 수 있는 10회차는 나아짐 4 · 같음 4 · 조금 나빠짐 2. 새 고칠 곳 18건을 v1.1에 반영했다. 보고: [`docs/시험/스킬시험_v1.1.md`](docs/시험/스킬시험_v1.1.md)
- 시나리오 · 채점 기준 · 회차마다의 대화 기록(transcript) · 산출물(final) · 채점은 [`docs/시험/`](docs/시험/README.md)에 그대로 넣었다(1차 `results/` 28회차, 재시험 `results_1103/`). 공개하며 고친 곳은 그 폴더의 README에 적었다.
- v1.2 ~ v2.0(11/3)은 고친 문장 대조만 했고 대화 시험은 다시 돌리지 않았다.

## 아직 안 된 것
- **결과 박스 숫자는 실제 사례로 검증하지 않았다.** 결과 박스(다 짠 배분 모양의 유형 — 검색 전환형 · 신규 전환형 · 인지형 · 리타겟형 · 혼합형)의 이름 · 경계는 가안이고, 비율 숫자는 가정값이다. 사람이 직접 짠 실제 사례와 스킬 안을 견주는 일도 아직이다.
- **v2.0은 대화 시험 전이다.** 시험 문제 묶음은 다시 세팅하는 중이다. 터미널에서 화면을 직접 읽고 파일로 쓰는 동작도 가안으로 둔 채 쓴다.
- **Codex · 제미나이 CLI에서 설치 자리의 스킬이 불리는지는 아직 시험하지 않았다.** 지금까지의 시험은 에이전트에게 스킬 파일을 직접 읽게 한 방식이었다. 시험 보고의 '제미나이'는 제미나이 CLI가 아니라 agy로 돌린 gemini 모델이다.
- **웹판은 v1.3에서 멈췄다.** 앞으로 터미널판만 고친다.
- 설계에서 확정을 기다리는 것은 [`docs/설계_질문.md`](docs/설계_질문.md)와 [`docs/설계_초안_v2.md`](docs/설계_초안_v2.md) 9장에 있다.
