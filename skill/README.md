# media-mix 스킬 v2.0(터미널판) — 설치 안내

이 문서의 경로(`media-mix/` · `media-mix.zip`)는 저장소 `skill/` 폴더 기준이고, `docs/` · `CHANGELOG.md`는 저장소 맨 위 기준이다.

대행사 마케터와 인터뷰하며 광고주의 **다음 기간 운영 계획안**(네이버 · 카카오 · 메타 · 구글 네 매체 사이 배분 + 매체 안 '상품'까지)을 짜 주는 스킬이다. 통계 기여 모형이 아니고, 캠페인 형식 · 세팅은 다루지 않는다 — 그것은 다음 단계(캠페인 세팅)다. **터미널(에이전트 환경)에서 쓴다** — 로그인은 마케터가 하고, 화면은 브라우저 도구로 읽기만 하며, 파일 · 계산 · 웹 검색 도구를 쓸 수 있으면 쓴다. 결과는 어떤 경우든 같은 묶음(계획안 표 · 점검표 · 광고주에게 보낼 메시지 · 광고주 기록 등 여덟 가지)으로 나온다.

- **판**: v2.0(11/3 — 터미널판으로 합치기 + 리타겟 결정). 판별 바뀐 것은 저장소 맨 위 [`CHANGELOG.md`](../CHANGELOG.md). 앞으로 터미널판만 고친다.
- **웹판은 v1.3에서 멈춤**: Claude 웹 · ChatGPT 업로드용은 더 만들지 않는다(11/3 결정).
- **권장 모델**: 기본은 소넷. 행사 다시 짜기 · 장기처럼 구간이 많은 판의 마지막 확인은 오푸스. 루나(gpt-6-luna)는 권하지 않는다(재시험 두 회차 모두 계획안 숫자가 무너짐). 솔(gpt-6.1-sol) · 아스트라(gpt-6-astra)는 재시험 세 회차에서 오푸스 · 소넷과 비슷했지만 표본이 작다. 제미나이(agy로 돌린 gemini-3.8-flash)는 재시험에서 할당량에 걸려 재지 못했다.

## 설치 — 터미널 세 곳
`media-mix/` 폴더를 통째로 아래 자리에 둔다(zip이면 풀어서). 폴더 이름은 `media-mix` 그대로, 안에 `SKILL.md`와 `references/`가 있어야 한다.

| 어디서 | 둘 곳 | 비고 |
|---|---|---|
| Claude Code | 모든 작업에서: `~/.claude/skills/media-mix/` · 이 작업 폴더에서만: `<작업 폴더>/.claude/skills/media-mix/` | 둘 다 있으면 작업 폴더 쪽을 먼저 확인한다 |
| Codex | `<작업 폴더>/.agents/skills/media-mix/` | |
| 제미나이 CLI | `<작업 폴더>/.gemini/skills/media-mix/` | |

- 세 곳 모두 같은 파일이다. 고친 뒤에는 세 곳을 같이 바꾼다(한 곳만 바꾸면 런타임마다 판이 갈린다).
- 설치(복사)는 쓰는 사람이 직접 한다. 스킬이 스스로 설치하지 않는다. 빈 폴더에서 바로 쓸 명령(`mkdir -p … && unzip …`)은 저장소 맨 위 [`README.md`](../README.md) '설치' 절에 있다.
- Codex · 제미나이 CLI가 이 자리의 스킬을 알아보고 부르는지는 아직 시험하지 않았다(지금까지의 시험은 스킬 파일을 직접 읽게 한 방식).

## 부르는 법
- 자연어로 부르면 스킬 설명에 맞춰 켜진다: "다음 달 미디어믹스 짜자", "새 광고주 제안용 미디어믹스", "블프 행사 예산 나눠 줘", "3개월 런칭 계획안", 계획안을 붙이고(또는 파일 경로를 주고) "미디어믹스 점검만".
- Claude Code는 `/media-mix`로 바로 부를 수도 있다. Codex · 제미나이 CLI에서 이름으로 부르는 법(예: Codex `$media-mix`)은 아직 써 보지 않았다 — 자연어로 부르는 것이 기본이다.
- 지난달 **광고주 프로필 · 다음 달 첫 말**을 붙이거나 그 파일 경로를 주면 "지난달과 바뀐 것" 한 질문으로 시작한다.

## 브라우저로 화면 읽기 — 로그인은 사람
- 광고 관리자 · 자사몰 관리자 · 네이버 키워드 도구는 **마케터가 브라우저에서 로그인해 둔다.** 스킬은 비밀번호 · 인증 코드를 받지 않는다.
- **브라우저 고르는 순서**: ① 사용자가 정해 둔 브라우저 설정(쓰는 환경의 지침 · 기본 브라우저 도구 등)이 있으면 그대로 따른다 ② 없으면 쓸 수 있는 브라우저 도구로 읽기만 한다 ③ 못 읽으면 값 · 캡처 · 내보내기 파일로 받는다. 스킬은 특정 브라우저 도구를 정해 두지 않는다.
- 읽을 수 있으면 스킬이 "로그인해 둔 ○○ 화면을 읽어도 될까요?"라고 묻고 **읽기만** 한다(설정 · 예산 변경 금지). 질문 수는 늘지 않는다.
- 읽지 못하거나 화면이 막히면 그 자리에서 값 · 캡처 · 내보내기 파일로 받아 계속한다. 내보내기 파일(CSV · XLSX)은 경로를 주면 스킬이 직접 읽는다.
- 금액 합 · 한도 · 하한은 계산 도구로 셈하고 식을 보인다.

## 써 보기
- "새 광고주 제안용 미디어믹스 짜자" → 카드 0부터(입구 · 브랜드 · 되는 것 고르기)
- "A사 다음 달 미디어믹스" + 프로필 블록(또는 파일 경로) → 프로필 확인 + "지난달과 바뀐 것" 한 질문으로 시작
- "블프 행사 예산 1,000만 원 나눠 줘" → 프로모션 자료(대상 제품 · 기간 · 할인율 · 콘텐츠 업로드일)를 받아 구간 블록으로
- "12월~2월 신제품 런칭 미디어믹스 짜 줘" → 장기: 방향 두 장(월별 방향표 · 역할별 매체 전략표) + 첫 달 계획안 일곱 칸
- 모르는 값은 "모름"이면 된다 — '확인 못 함'으로 두고 계획안 7칸 '광고주에게 받을 것'으로 넘긴다.

## 쓰면서 알아 둘 것
- 한 번에 질문 3개 이하로 묻는다. 새 광고주 · 평시 기준으로 스킬이 대략 열 차례 답하면 산출물 한 벌이 다 나온다(카드 0 → 1-가 · 1-나 · 1-다 · 1-라 → ✋ 1 → ✋ 2 → 카드 3~7 계산 요약 → 카드 8 · 9 + ✋ 3 → 카드 10). 상시 · 프로필이 있으면 카드 1이 두세 차례로 줄어든다.
- 광고주용 본은 따로 한 덩어리로 나온다 — 그것만 광고주에게 보낸다. 입력 카드 · 점검 결과 · 결과 박스는 내부본이다.
- 스킬은 광고 설정을 바꾸지 않고, 메시지를 보내지 않는다. 계획안은 **기본으로 작업 폴더에 파일로** 쓴다 — 광고주용 본 · 내부본 · 근거 숫자(CSV), 카드 10 뒤 광고주 프로필. 경로를 주면 그 자리에, 안 주면 `미디어믹스/<광고주>/<집행 시작 연월>_<판>판/` 아래 정해 둔 이름으로 쓰고 쓴 경로를 말한다(`references/plan-template.md` 11절). 다음 달에는 `광고주프로필.md` 경로를 주면 이어서 시작한다.
- 오류 2 · 9 · 11([판단])은 하위 에이전트를 쓸 수 있으면 점검 묶음만 주고 따로 읽힌다('별도 에이전트가 읽음'). 못 쓰면 같은 대화에서 읽었다고 적는다.
- 리타겟은 계획 단계에서 따로 재지 않는다 — 모수가 적으면 매체가 덜 쓰고, 덜 쓰인 돈은 신규 유입으로 옮긴다(6칸 한 줄).
- '(가안)'이 붙은 규칙은 설계 9장에서 확정을 기다리는 것이다(`references/provisional.md`). 터미널판 동작도 시험 전이라 가안 목록에 있다.

## 고칠 때
정본은 설계 문서다. 스킬 문구는 정본을 요약해 옮긴 것이라, 정본이 바뀌면 아래 짝을 같이 고친다. 공개본에는 정본 가운데 [`docs/설계_초안_v2.md`](../docs/설계_초안_v2.md)만 넣었다 — 단계 표 · 규칙표 · 카탈로그 정본 같은 나머지 설계 메모는 공개본에 없다. 설치되는 스킬 파일(`media-mix/`)에는 정본 출처를 적지 않았다 — 설치한 에이전트가 없는 파일을 찾으러 가지 않게, 출처는 아래 표에만 둔다. v2.0의 터미널 전제는 설계 v2 1-1(웹 대화 · 터미널 두 환경)과 어긋난다 — 정본 반영 자리는 [`docs/설계_질문.md`](../docs/설계_질문.md) 고침 8 절.
