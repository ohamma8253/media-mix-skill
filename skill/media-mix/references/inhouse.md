# 부록 — 인하우스 패스 (10/29 결정: 부록)

브랜드 안에서 광고를 운영하고 랜딩 · CRM도 직접 바꿀 수 있는 경우다. 카드 0 '되는 것 고르기'에서 **둘 다**(내부 데이터 보기 + 랜딩 · CRM 바꾸기)를 고르면 이 패스다. 판단 순서 · 품질 기준 · 양식은 본문 그대로 쓰고, 달라지는 곳만 여기 모은다. 받은 입력을 보고 스위치를 다시 맞춘다(마진을 못 받으면 E를 끈다).

- **아직 가안**: 2단계(랜딩 개선 후보) · 4단계(CRM과 나눔) · 7~8단계(랜딩 · CRM 시험) 줄은 패스 항목을 넓혀 적용한 가안이고 확인받지 않았다. 이 줄을 쓴 자리에 '(가안)'을 붙인다.
- **켜지는 항목**: B1 · B2 기본, E는 데이터가 있으면 기본, F에 내부 축(회원 / 비회원, 신규 / 기존 / 부활), H는 내부 결정.

| 카드 | 대행사 패스와 다른 점 |
|---|---|
| 0 시작 | 광고주를 웹에서 찾아볼 필요가 적다. 내부 자료 위치(주문 원장 · 고객 데이터)를 묻는다 |
| 1 모으기 | B1 · B2 · E 입력을 기본으로 받는다. 내부 브랜드 · 직접 유입(구글 애널리틱스 등)도 가져온다 |
| 2 진단 | 전환 효율 하락이면 매체 대신 **랜딩 · 상품 페이지 개선**도 대응 후보로 둔다(가안) |
| 4 역할 비중 | 리타겟 몫을 CRM(메시지 · 쿠폰)과 나눠 본다. 광고비가 아닌 CRM으로 풀 수 있으면 광고 금액을 줄인다(가안) |
| 7~8 예상 · 계획안 | 6칸 시험에 랜딩 · CRM 변경을 같이 넣을 수 있다(가안) |
| H 꺼 보기 | 내부 결정으로 정한다 |
| 10 다음 작업 | 광고주 컨펌 대신 **내부 공유 · 실행 목록**(캠페인트리, 랜딩 · CRM 작업, 점검 날짜) |

**산출물 한 벌에서 바뀌는 것**
- 1 머리표: 상태는 광고주 확인 대신 **'내부 공유'**.
- 2 입력 카드: 켠 항목에 E · B1.
- 6 보내는 메시지: 컨펌 메시지 대신 내부 공유.
- 7 남기는 기록: 프로필 갱신 · 점검 날짜.
- 8 다음 뎁스: 랜딩 · CRM 작업(캠페인트리는 이 스킬 밖 — '요청 있음'만).
- 내부 실행 목록은 새 산출물이 아니다. 6 · 7 · 8에 나눠 들어간다.

**대행사 패스 + 데이터**(내부 데이터만 볼 수 있는 대행사)는 인하우스가 아니다 — 본문 대행사 패스에 `judgment.md` 1절 '대행사 + 데이터에서 더하는 것'을 켠다. 랜딩 · CRM 수정은 '광고주에게 제안할 것'으로 적는다.
