최종 회차 채점 파일 22개(s1 둘 · s2 여섯 · s3 다섯 · s4 셋 · s5 여섯)의 '스킬에서 고칠 곳'을 모아 중복을 합쳤다. 1회차(`-r1`) 채점 파일은 쓰지 않았고, 1회차 비교는 `고칠곳_1회차_소넷.md`의 번호로 했다. 모델 수는 같은 항목을 짚은 모델의 수다(괄호 안은 모델 이름). 1~5번이 맨 위 후보(여러 모델에서 나왔거나 계획안 숫자를 틀리게 만든 것)이고, 6~20번은 여러 모델에서 나온 것, 21번부터는 한두 모델에서만 나온 것이다.

## 설계 미정(확인 필요)

스킬 실패로 세지 않는다. 준비_보고 13건 중 최종 회차에서 다시 나온 것, 1회차 뒤 `설계_질문.md` 11~13, 채점 파일에서 새로 나온 확인 후보를 묶었다.

**설계 확인 목록**
- D1. **두 줄 클릭 공유 규칙과 예시의 금액 한도 520이 충돌한다.** 예시(와 채점의 일반 한도 520)는 일반 키워드 한 줄 단독으로 센 값인데, 스킬의 공유 규칙(가안)은 파워링크 + 쇼핑검색 클릭 합을 월평균 클릭수에 묶는다. 같은 규칙으로 s1 1판(일반 210 + 쇼핑 250 = 클릭 7,625)도 한도를 넘는다. 공유 규칙을 정본으로 둘지, 예시 숫자를 고칠지 정해야 한다. (s5-astra · s5-opus · s5-sonnet · s1-gemini · s1-opus, 5회차 모두 같은 원인)
- D2. **진단("같은 역할 안에서 옮김")과 한도 초과분 이동 중 무엇이 먼저인가.** 한도 식이 검색 90을 신규 유입으로 옮겨 비중이 53.8% → 45.8%로 바뀌고 박스가 달라진다. 넘친 돈을 수익률이 목표보다 낮은 메타로 보내도 되는지도 같은 질문. (s5-opus · s5-sol · s1-opus)
