# s1 시험 메모

## 실행 범위
- PROMPT_web.md에 따라 로컬 skill/media-mix/SKILL.md와 필요한 references만 사용했다. 자동 목록의 상위 media-mix는 호출·열람하지 않았다.
- 시나리오는 scenarios/s1-regular-replan/scenario.md만 읽었다. 업로드 차례를 기록한 뒤 data/매체별_월별_2026-08_10.csv만 읽었다. 다른 시나리오 자료·상위 test/results는 읽지 않았다.
- 사용자 공통 정책 파일은 세션 시작 사용자 지시에 따라 한 번 읽었다. 시험 자료의 유일한 작업 폴더 밖 읽기 예외다. 자동 상위 스킬이나 상위 프로젝트 지침을 찾지는 않았다.
- 웹 검색·브라우저·광고 관리자 접속·외부 API·계산 도구·에이전트 위임을 사용하지 않았다. 수치는 직접 계산했다.
- 파일 내용을 읽을 별도 로컬 파일 도구가 없어 셸을 지침·스킬·업로드 파일 읽기와 결과 텍스트 검사에 사용했다. 결과 기록은 apply_patch로 했다. 셸·스크립트로 미디어믹스 계산이나 시나리오 답 생성은 하지 않았다. 따라서 '셸 명령을 쓰지 않는다'를 도구 사용 전체의 문자적 금지로 해석하면 이 읽기 작업은 예외다.
- 대화는 가상 사용자와 스킬 역을 구분한 로컬 모의 대화다. 실제 사람에게 질문하거나 확인을 기다리지 않았고 실제 발송·집행·광고주 합의를 주장하지 않았다.

## 카드별 관찰·고칠 곳
- 카드0·1-가: 실제 환경 날짜와 시나리오 날짜가 다르다. 오늘 날짜를 명시적으로 받아 시나리오의2026-10-27로 진행했다. 웹 시험용 날짜 우선순위를 지침에 명문화하면 혼동이 줄어든다.
- 카드1-나·2: 10월은10/26 실적의 월말 환산치다. 8~9월 확정 비교로 단가 상승을 진단하고10월은 잠정 참고로 분리했다. 월별 표에 실적일수와 환산 여부 칸을 고정하는 편이 좋다.
- 카드1-나·7: 카페24 결제액 부가세 포함 여부를 물어서 받아야 ROAS가 맞는다. 49,500÷1.1=45,000원을 사용했다. 매체 전환값도 모두 구매당45,000원인 파일이지만, 그 값의 세금 포함 여부를 새로 받은 사실처럼 쓰지 않고 구매×자사몰 세전 객단가 환산으로 명시했다.
- 카드1-라·✋1: 한 질문의 모수·친구·수신동의·빈도와 다른 질문의 이미지·영상·상품 등록·문구가 여러 화면에 걸친다. 스킬 예시 자체가 '괄호 보조 값 둘까지'와 충돌할 여지가 있다. 이번 시험도 묶음 요청을 사용했다. 화면별 질문 분리와 필수값 우선순위가 필요하다.
- 카드3·5: 브랜드검색30일 견적을 모르면 카탈로그의 범위 안에서 특정 편성액을 고르는 규칙이 충분하지 않다. 이번70만은 같은 상품의 지난30일 계약70만을 우선한 견적 확인 전 금액이다. 다른 계약 기간으로 환산하지 않았다.
- 카드4·5: 목적형 순서와 단가 상승 시 역할 유지 지침을 따르려 해도, 공유 검색 클릭 한도가 과거 일반+쇼핑 합보다 작다. 이번에는 일반을 줄이고 한도를 지킨 뒤 남는 돈을 신규에 배정했다. 진단 규칙과 한도 규칙 충돌의 우선순위가 더 명시적이면 좋다.
- 카드5: 애드부스트 쇼핑을 파워링크+쇼핑검색 공유 클릭 합에서 제외하는 규칙을 그대로 적용했다. 이 제외가 실제로 검색 수요의 독립성을 뜻하지는 않으므로 차후 규칙 검토가 필요하다.
- 카드3·10: 시나리오의11/1~4 실제151만과 상품별11/28/33/8/61/10만은 '1판 하루 금액대로'라는 말과 이번 산출1판 금액이 정확히 일치하지 않는다. 실제 상품별 금액을 우선하고11/5에만1판 하루액을 적용했다. 이 시나리오를 여러 계획안에 공통으로 쓸 경우 '계획대로'를 빼거나 실제 지출을 별도 값으로 명확히 주는 편이 낫다.
- 카드5·9: 이미 쓴 구간의 공유 검색 클릭 한도를 소급해서 지킬 수는 없다. 스킬이 지시한 남은 구간 감액으로 월 합을 보정하고 실제 초과를 표에 남겼다. 점검5는 이 보정 후 통과로 표시했으며 실제 구간 초과 사실을 지우지 않았다.
- 카드1-다·3: 본 행사1.6배는 문턱을 넘지만 행사 뒤1.2배는1.3 미만이다. 구간별 문턱 원문에 따라 뒤는1로 적용했다. 이미 행사 자료가 있는 달의 검색량 배수에도 같은 문턱을 적용할지 명문화가 필요하다.
- 카드7:25% 할인만으로 행사 객단가를 계산할 수 없다. 행사 판매 구성·기존 실결제액이 없으므로45,000원 유지 가설을 표시하고 가능한 예상 결제 객단가를 요청 항목으로 넘겼다. 이 자료를 다시 짠 판 입력 질문에 기본 포함하면 좋다.
- 카드7·9: 공유 검색 한도는 클릭 단가가 커질수록 허용 예산이 커진다. 한도를 통과하려고 추정 단가를 높이지 않고, 일반800원은 도구값·쇼핑500원은 지난 기록 보수값을 예상과 검사에 함께 썼다.
- 카드9: '오류11줄(8-1·8-2 포함)'과 명시 번호1~11 및8-1·8-2가 동시에 있어 행 수가 모호하다. 번호 누락 없이13개 검사 행으로 기록했다.
- 카드9: 독립 새 대화 검토를 실행한 것처럼 쓰지 않았다. 같은 대화에서2·9·11을 읽고 새 대화 점검 묶음을 제공했다.
- 카드10: 계획안 긍정은 대행사 마케터의 검토 완료다. 최종 상태는 광고주 확인 대기로 유지했다. 프로필은 복사할 초안이며 실제 계정·CRM 저장을 뜻하지 않는다.

## 시나리오에 답이 없어 '모르겠어요'로 넘긴 질문
- 카드1-가: 메타·구글 대행 수수료율.
- 카드1-다: 이번 브랜드검색 계약 견적.
- 카드1-라: 쇼핑 상품 등록·파워링크 문구 준비 여부, 카카오 수신동의 수.
- ✋2: 판매처 월 신규 고객 수.
- 두 판 카드3~7의 '계속' 안내: 시나리오에 별도 계속 응답이 없어 '모르겠어요'로 진행. 스킬은 답이 무엇이든 카드8로 가라고 하므로 멈추지 않았다.
- 2판 입력의 행사 전환율과 카카오 발송 단가는 시나리오가 명시적으로 모른다고 정한 값이다. 빠진 답을 지어내지 않았다.
